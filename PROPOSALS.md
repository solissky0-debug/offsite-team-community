# 提案与自主成果 / Proposals and independent candidates

OffsiteTeam 是让人在线找工作、组团队、完成项目的工作平台。本仓库帮助大家共同改善这个目标；欢迎先提出有依据的问题，也欢迎展示独立完成的小成果。**提出者不必亲自实现；展示者不必先认领正式任务。**

## 路径一：有据提案

先搜索已有讨论与任务，再到 [Ideas · 改进提案](https://github.com/solissky0-debug/offsite-team-community/discussions/categories/ideas) 发起讨论。可用中文或英文，建议写清：

1. **问题与受益者**：谁在什么场景遇到什么障碍？与在线工作、组队或交付有什么关系？
2. **依据与反例**：附有权公开的资料、可复现观察或合成示例；分开事实、推测、个人偏好和待核实项，也说明可能反对这个方案的证据。
3. **最小建议**：希望改变什么，哪些暂不做？现有替代办法和成本是什么？
4. **成功标准**：什么可观察结果能说明改善有效？没有证据时，提出一个小规模验证办法。
5. **参与意愿（可选）**：只提建议、愿意讨论、愿意独立制作候选，均可。无需承诺开发或长期维护。

其他人可以支持、补充证据、提出反例或帮助缩小范围。维护者整理 [决策摘要](DECISION_TEMPLATE.md)，交由项目发起人确认是否立项。缺少证据可以保持待验证；暂缓或不采用应写明原因，不因支持数自动进入开发。

## 路径二：自主候选成果

可以自行制作与目标有关的小型原型、双语术语表、设计建议或合成样例评审，在 [Show and tell · 自主成果](https://github.com/solissky0-debug/offsite-team-community/discussions/categories/show-and-tell) 展示。先限制投入，用自己有权公开的材料制作。

- 写明对应问题、来源讨论或现有任务、交付版本、可公开预览、验证方法与局限。
- 标明“自主候选，待评审”，区分实际测试、合成演示和建议；不把候选描述为官方交付、已验收或已发布。
- 说明内容来源、第三方限制、AI 辅助和允许评审的范围。按 [权利说明](RIGHTS.md) 保留权利；产品采用或商业使用前先明确相关授权。
- **公开展示不保证采用、付款、贡献登记或正式任务资格**，也不授予私有源码、真实数据、部署、账号、数据库或资金访问权。未事前约定的工作不构成平台欠款。
- 不提交私有源码、生产配置、客户文件、真实用户数据、私人作品或草稿、密钥、验证码、私人邮箱、聊天原文及认证链接。不需要获取这些材料来参加讨论。

若已有 OST-COM-001/002/003 与成果相关，引用原任务，不新建同名任务或仓库。维护者可邀请进入后续评审；是否正式采用仍需范围、权利、独立验收与项目发起人的决定。

## 路径三：正式任务

正式任务由已确认的决策摘要连接到 Issue；先写清负责人、交付范围、验收标准、依赖与报酬状态，再开放认领。**目前正式认领与贡献登记仍暂停，等待 V15 共建账号流程的真实用户验收及明确开放公告。** 发布了入口不等于流程已经验收。

开放后，正式参与者须完成本站邮箱验证、固定 OffsiteTeam 编号及 GitHub 账号关联核实，再由维护者确认认领。详见 [参与指南](CONTRIBUTING.md)。自主展示不能绕过正式任务门槛。

## 支持、决定与证据

**支持 ≠ 立项 ≠ 验收 ≠ 发布。** GitHub 原生 reactions、upvotes 或 polls 仅表达该平台账号的意见，不是本站验邮成员投票，也不代表真实姓名核验或一人一票治理。支持数不授予预算、经济权益或生产权限。

项目发起人（项目所有者）保留立项和发布决定权；维护者整理范围和证据，独立审核者检查交付。讨论被标记回答、Issue 被关闭或 PR 被合并，都不能单独证明已验收或已发布。请保留以下公开证据链，无对应结果就明确写“尚无”：

`Discussion → 决策摘要 → 正式 Issue / 任务 ID → 交付 PR / 固定版本 → 独立验收 → 发布批准 → 发布版本与验证证据`

协作求助使用 [Q&A](https://github.com/solissky0-debug/offsite-team-community/discussions/categories/q-a)，确认过的进展使用 [Announcements · 官方更新](https://github.com/solissky0-debug/offsite-team-community/discussions/categories/announcements)。本站当前没有自建论坛、实名投票或自动派单；任何外部内容都须人工审核后才能形成执行任务。

## English

OffsiteTeam aims to help people find work, form teams and complete projects online. Choose one of three paths:

1. **Evidence-based proposal — [Ideas](https://github.com/solissky0-debug/offsite-team-community/discussions/categories/ideas).** Describe the problem and audience, public evidence and counterexamples, a small proposed change, alternatives, and observable success criteria. Separate facts, assumptions, preferences and unknowns. The proposer is not required to implement the idea or promise ongoing maintenance. Others may support, question or improve it. Maintainers summarize the evidence; the project owner decides whether to authorize a formal task.
2. **Independent candidate — [Show and tell](https://github.com/solissky0-debug/offsite-team-community/discussions/categories/show-and-tell).** You may independently prepare and display a small prototype, terminology table, design or synthetic review without claiming a formal task. Label it an unreviewed candidate and include its source discussion or existing task, version, preview, validation limits, authorship, third-party rights and AI use. Public display guarantees neither adoption, payment, contribution registration nor eligibility for assignment. It grants no access to private source, production data, accounts, deployment, databases or funds. No prior paid agreement means no payment obligation. Resolve incorporation rights before adoption under [RIGHTS.md](RIGHTS.md).
3. **Formal task — [Issues](https://github.com/solissky0-debug/offsite-team-community/issues).** An owner-approved decision links to an Issue with scope, acceptance criteria, dependencies, reviewers and compensation status. **Formal claiming and contribution registration remain on hold pending real-user acceptance of the V15 community account process and an explicit opening announcement.** Once opened, verified OffsiteTeam email, a permanent platform number and verified GitHub association are required. Independent display does not bypass these conditions. Reuse OST-COM-001/002/003 when applicable; do not create duplicate tasks or repositories.

**Support ≠ task authorization ≠ acceptance ≠ release.** GitHub reactions, upvotes and polls are GitHub-account feedback, not verified-email membership voting on OffsiteTeam, legal-name identity verification or one-person-one-vote governance. The project owner retains task authorization and release decisions. Maintainers organize evidence; someone other than the submitter reviews acceptance. An answered discussion, closed Issue or merged PR does not by itself prove acceptance or release.

Preserve links from discussion to [decision summary](DECISION_TEMPLATE.md), formal Issue/task ID, versioned deliverable, independent acceptance, release approval, and release/version evidence. Mark unavailable results as pending. Use [Q&A](https://github.com/solissky0-debug/offsite-team-community/discussions/categories/q-a) for collaboration help and [Announcements](https://github.com/solissky0-debug/offsite-team-community/discussions/categories/announcements) for confirmed official updates. These are existing GitHub categories; their displayed names remain English.

Use only material you may publicly share. Do not submit private source, production configuration, client files, real user data, private work or drafts, secrets, verification codes, private email addresses, private chats or authenticated URLs. This workflow creates no on-site forum, identity voting or automatic assignment/execution system.
